File Formats Guide

HeadAnalyser V2 accepts CSV, Excel (.xlsx), and JSON files. This page describes the expected structure, required columns, and the auto-detection behaviour.

CSV & Excel Files

Data should be arranged with one row per measurement point and columns for each attribute. The first row is treated as a header.

Required Columns

FieldDescriptionExample header names
Point IDUnique identifier for each well or measurement point.ID, PointID, Well_ID
X CoordinateEasting or longitude of the point.X, Easting, Longitude
Y CoordinateNorthing or latitude of the point.Y, Northing, Latitude
Hydraulic HeadWater-level measurement (metres above datum).Head, Hydraulic_Head, WaterLevel

Optional Columns

FieldDescription
Top ScreenTop elevation of the well screen (m).
Bottom ScreenBottom elevation of the well screen (m).
DepthMeasurement depth (m). Used by the depth range filter.

JSON Format

JSON files should contain a top-level "data" array of objects. Each object represents one point and uses keys that match the column names described above:

{
  "data": [
    { "ID": "W-01", "X": 720145.2, "Y": 6178321.5, "Head": 12.34 },
    { "ID": "W-02", "X": 720210.8, "Y": 6178405.1, "Head": 11.87 }
  ]
}

Column Mapping Dialog

When you open a file, HeadAnalyser tries to auto-detect the four required columns by matching common header names. If auto-detection fails (or matches incorrectly), the Column Mapping dialog appears and lets you assign each field manually via dropdown menus.

Tip: Make sure your coordinates use a consistent projection system. HeadAnalyser assumes a metric coordinate reference system (e.g. UTM) for gradient calculations. The Map view converts from UTM32N (EUREF89) to WGS84 automatically.
Warning: Rows with missing or non-numeric values in the required columns are silently dropped during import. Check the point count in the status bar to confirm all rows loaded correctly.
